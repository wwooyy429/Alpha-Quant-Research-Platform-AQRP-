# 自动化测试与人工审查总方案

关联 QA-001–007、INT-001–006。P0 只有文档结构自查，不存在业务测试通过结果。测试设计/预期不等于运行证据。正式代码从 P1 开始同步建 pytest 和 GitHub Actions；不因测试要求而提前做后续模块。

## 测试层及风险目标（待批准）

| 类型/模块 | 设计要求 | 拟最低覆盖目标 |
|---|---|---|
| 时间/PIT、金融原语、风险、撮合/账本 | 已知答案+边界+性质+独立参考，关键分支与状态转移必须逐项测 | 行95%，分支90%，列明的关键不变量100%有案例 |
| 其他核心/Registry/研究/服务 | 单元、契约、集成、回归、失败路径与版本兼容 | 行90%，分支85% |
| UI/CLI/Competition薄适配 | 请求映射/显示完整、错误安全、同核集成 | 行80%，分支70%，关键用户流程100%有案例 |

这些目标是 P0 提案，需随计划预审/人工批准成为基线。覆盖率不替代答案核对；关键业务分支未测即使总体达标也阻断。性能测试在有实际数据规模/硬件/时限后预注册阈值（D-008），不虚构秒数。

## Future Data Mutation Test

固定 cutoff 与历史快照可见投影，先保存过去信号；变更 event_time>cutoff 或 available_at>cutoff 的价格/行动/财报/成员与未来修订，再重新查询/计算。过去信号/参数与hash投影一致。修改在 cutoff 前不可见但 event_time 更早的修订，同样不得影响历史。反向控制：改变 cutoff 前已可见合法数据应影响依赖输出，避免“函数一直返回常数”假通过。独立检查查询谓词、权限和缓存键；mutation 相同不是无泄漏证明。

## Factor Replacement Tests

- T-REPL-2（P2）：固定DataView，注册/resolve Momentum→Reversal，仅改精确FactorRef，元数据/参数/major/停用回滚正确；不调用研究/回测。
- T-REPL-3（P3）：固定研究配置与快照，运行完整研究链两次，原始分数与统计按独立答案变化，处理/验证/报告核心无修改。
- T-REPL-5（P5）：固定组合/风险/执行/现金/数据，仅改因子配置，各跑完整策略链，信号/目标/订单改变符合定义、账本各自正确；保存组合/风险/引擎核心文件哈希与diff。
- T-REPL-6（P6）：相同FactorRef与规范配置在CLI/服务/UI选择和研究/回测结果一致，忽略run_id/墙钟等非数值元数据。
- T-REPL-7（P7）：固定代码SHA、市场快照、组合/回测配置，Momentum全研究+策略→保存→仅改因子选择→Reversal全链→证实无需改核心→全部适用回归。预先选不会因阈值产生同一订单的合成数据，用独立预期对照；结果不同不要求收益相同。

## 关键不变量与独立答案

不能读未来、不能跨证券滚动；权益=现金+持仓+应收−应付；费用不消失/不双扣；风险约束不能绕过；订单转移合法；未批准因子拒绝策略；重复事件幂等；同版本可复现；CLI/UI同核。每项需最小正例、负例、边界和独立数值/状态参考；见 GOLDEN_DATASET。

代码作者测试和 Gemini独立核对分别存证。Gemini初始只读；未经授权不执行不可信代码。其独立测试仅在用户允许的隔离环境/audit分支运行，通过PR提交，不直接修改main或GPT开发分支。人工复算现金/统计答案是正式验收的一部分，AI共识不代替。

## 证据要求

每次运行存完整SHA、命令、工作目录、UTC开始/结束、OS/Python/锁文件、数据manifest、退出码、原始stdout/stderr、测试报告/覆盖率、通过失败跳过数、产物hash、已知限制。CI用run_id/attempt/job链接关联SHA；本地日志不能冒充CI。跳过须列依赖/理由，不纳入“已通过”。修复后新SHA重跑并链接缺陷复核。

P7干净环境必须实际获取源代码→固定依赖安装→准备测试数据→自动测试→CLI研究→CLI回测→Streamlit启动/任务→数值比对→日志封存。未运行不得称部署验收通过。操作手册和部署文档在P7补齐。
