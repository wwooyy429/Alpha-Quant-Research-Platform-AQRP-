# 文档自查中已处理的问题

这些是开发方发现及修复记录，不能代替Gemini缺陷报告。

1. Windows文档编制工具的默认换行产生CRLF，首次暂存格式检查出现行尾告警。已将生成器及自查输出明确设为UTF-8/LF；原始V3.0/V3.2附件保留原字节，只为这两份来源声明CR为行尾组成。后续实际 `git diff --cached --check` 退出码0，没有通过关闭所有空白检查隐藏格式问题。
2. 百度同步短暂生成临时元数据与一份 requirements 冲突副本，并将正式CSV换行为CRLF。逐行解析比较确认正式CSV和冲突副本的105条/所有字段均与已提交版本相同，仅换行不同；正式文件恢复已提交字节。冲突副本保留在本地，精确文件名加入忽略，不删除任何不同的用户编辑。MANIFEST只枚举Git可追踪交付文件，排除同步元数据及已确认副本。

如后续再次出现同步修改，先比对语义和Git差异，不自动覆盖；固定审查对象以完整Commit及文件hash为准，不能以实时同步目录替代。上述修复未改变需求语义、业务功能或独立审查状态。
