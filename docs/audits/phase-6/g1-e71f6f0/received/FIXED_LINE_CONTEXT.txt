1: # 固定三种Task的完成屏障与恢复契约（G1修订候选）
2: 
3: 本契约修订WORK-P6-G1-001，供新固定SHA独立复核，发现仍OPEN_PENDING_RECHECK；不是P6实现。Task的成功与任一核心子run的成功严格分开。核心终态只更新它所属的slot；只有TaskService完成本文件的全Task屏障和提交，才可发布Task SUCCEEDED。没有通用DAG/插件调度框架。
4: 
5: ## 固定kind、必需阶段和产物
6: 
7: | kind | 冻结的必需阶段 / slot | 成功的必要证据 |
8: |---|---|---|
9: | research | R=一次P3研究；RV=研究工件验证/发布 | R的真实SUCCEEDED终态、原始report/metrics/审批建议/全部manifest成员与输入/家族记录绑定；RV验证回执；Task全局完成回执 |
10: | engineering_pipeline | R=P3研究 → PLAN=冻结P5请求和决策集合 → B=P5模拟，内部P[i]=逐决策P4 → BV=全链验证/发布 | R真终态、不可变ResolvedPlan、B真SUCCEEDED及已核金融投影、全部必需P[i]真SUCCEEDED和P5实际portfolio-lineage一致、BV全链工件/来源验证及Task回执 |
11: | replay | SV=原run/包/锁/投影范围验证 → E=声明范围内实际重放（含其内部P4 slots，如适用） → CV=独立比较/封存 | SV回执、E实际NUMERICAL_REPLAY_VERIFIED或目录已登记的原Ref投影重放成功、CV比较与目标工件清单、Task完成回执；原run成功仅是SV输入 |
12: 
13: RV/PLAN/BV/SV/CV是受限编排的校验/封存步骤，不伪装成既有P3/P4/P5业务run。其原始输入hash、声明投影、结果与检查证据都写不可变Task工件清单。replay仅允许catalog登记的P5_NUMERICAL或PUBLISHED_REF_PROJECTION；不支持的旧宿主/缺包范围明确拒绝，不能把验证原始源文件当执行了重放。
14: 
15: engineering_pipeline不另造外层假P4 run：必需P4就是P5内部真实逐决策调用。R验证后，用原P3/P1来源、共享builder和已冻结有效配置构造P5请求；这只是请求/来源组装，不重复拟合或改PIT。先冻结ResolvedPlan（父TaskPlan hash、P5请求原字节/hash、严格有序决策表index/decision_time/source-request hash、N、每个必需slot/UUID/root）。N取已验证请求decisions的完整集合，本应用流水线要求N>=1；空区间在此以NO_REQUIRED_DECISIONS明确拒绝，不修改底层P5合法零决策API。ResolvedPlan在B启动前持久化，之后不能缩减N、删失败/缺失slot或事后追加替代UUID。P[i]适配请求hash在调用前按NESTED_CONTEXT_CONTRACT做一次性finalize。
16: 
17: ## 成功屏障
18: 
19: TaskService在可信同一claim中逐项确认：
20: 1. 有效配置/初始TaskPlan、必要时ResolvedPlan、catalog/defaults、代码/bundle/core与UI锁/输入快照及侧车身份全部一致；plan已封闭，固定必需slot集合完整且实际注册调用集合精确对账，无遗漏/多余/未登记run。
21: 2. 每个必需slot的服务类型、Task/parent/decision/root/config绑定已核；各核心真实终态和原始manifest/成员hash通过既有完整门禁。R/P[i]/B均真实SUCCEEDED；RV/BV/SV/CV相应验证回执完整。replay的E必须有本次实际重放/比较证据，不能借原run的SUCCEEDED替代。
22: 3. B成功必须具有原始result/state/transactions/transaction-files/portfolio-lineage/published-byte-audit/trace等manifest内所需工件及既有完整金融对账证明。每个P[i]原始result/candidate/risk/成功审计与B对应决策/真实父链一致；只凭P5返回success或一个合法UUID不足以通过。
23: 4. 没有运行中的worker/未处理副作用或未决取消；取消与完成竞争在同一任务终态事务串行化。若完整成功屏障先完成并提交，后来的取消TOO_LATE；若取消意图先被接收，禁止继续提升成功，等待安全取消/对账。未知财务状态一律FAILED+COMMITTED_STATE_UNVERIFIED，不能CANCELLED known=true。
24: 5. 所有上述证据写成一次性completion.json，列出task/kind/config/plan hashes、完整required slots及绑定、各终态/产物/父链hash、验证结果和最后claim。先原子发布并验证回执，再在SQLite事务内检查同一plan/claim/取消版本并提交Task SUCCEEDED及回执hash。两侧未闭环时仍RUNNING/finalizing，不因文件存在报成功。
25: 
26: SQLite提交前宕机，恢复者重新验证整个屏障及completion.json，才可追加恢复Task终态；绝不能从一个恢复的P3/P4终态提升整个Task。SQL终态若指向丢失/损坏回执，保留原记录并对外标INTEGRITY_ERROR/usable=false，不作为成功计数，也不重写旧证据来维持成功。
27: 
28: 这是明确的应用级严格全链成功口径：合法P4风险拒绝仍保留真实P4 REJECTED/FAILED与P5可能SUCCEEDED的原始事实，但该Task以FAILED/REQUIRED_STAGE_REJECTED展示，不能说全链所有必需阶段成功。此规则不改P5风险/事件/金融算法、不把拒绝改成下单、不强制中断原模拟，也不要求成交数或收益为正。所有真实子结果可按各自状态查看。
29: 
30: ## 恢复与未完成阶段
31: 
32: | 观察到的可信状态 | 只允许的恢复动作 | Task不能宣称的事实 |
33: |---|---|---|
34: | R终态已提交、slot映射未写；P4/P5尚未启动 | 核原预分配R绑定后恢复R slot；用其原字节组装/验证PLAN；只有未启动且ALLOCATED的后续slot可执行 | 不能Task成功，不能重跑R、重计或退还试验 |
35: | R/部分P[i]成功，B未形成终态 | 只恢复这些slots；严格满足原P5 resume条件时使用同一B run/请求/上下文和原始事务prefix恢复；否则RECOVERY_REQUIRED | 不能凭已完成P4或缓存余额成功，不能新建B替代 |
36: | R/P[i]成功，B缺失但START_INTENT已登记，或存在半初始化/部分发布 | FAILED/RECOVERY_REQUIRED，保留所有记录；不自动从缺目录推断未执行 | 不能自动重做或抹去已提交副作用 |
37: | B声称SUCCEEDED但缺必需P4记录/归属/原始工件 | FAILED/RECOVERY_REQUIRED；不能在B结束后补开P4来填清单 | 不能接受B的success字符串替代全链 |
38: | B真实FAILED、P[i]失败/拒绝、unknown或真实取消 | 分别记录全部子事实并按失败/安全取消规则归并；未运行后续slot标明未执行 | 不能删掉失败slot来满足all条件 |
39: | 全部必需slots、最终工件及父链成功，但Task回执/索引未提交 | 全量重验证，补完成回执/终态事务；不重新执行核心 | 不能在补验证之前发布成功 |
40: | 全部屏障、回执及终态事务通过 | 返回原Task和原子run引用，后续同key幂等读取 | 不能生成新核心run或覆盖历史 |
41: 
42: 只有slot仍ALLOCATED、无START_INTENT、无核心目录/初始记录且完整枚举和claim证据均能证明从未执行时，才可首次调用。任何枚举错误、未知/冲突、活跃旧claim、配置漂移都失败关闭。P5恢复只适用既有resume_engineering条件（同包/原config/原prefix、无部分发布等）；不能借Task恢复放宽原拒绝。replay是新执行且新归属，resume是同一执行同一slot，不能互换。
43: 
44: G2必须在真实服务/SQLite/磁盘执行R、每个P[i]、B、RV/BV/CV提交及映射前后、completion发布与SQL提交之间的断点，验证未完成任务不成功、无重复核心调用/试验或金融提交，取消竞态和原始失败仍完整。设计模型通过不代表这些实际故障已测。

1: # 可信上下文到P5内部P4的传播与物理目录（G1候选）
2: 
3: 本文件处理WORK-P6-G1-002，状态OPEN_PENDING_RECHECK。源事实：P5 Simulator._risk_portfolio现在调用construct_engineering(request, self.root/portfolio-runs, code_commit)，provider.verify_portfolio_result在同根核验，_submit还会复核；P5 replay又创建独立Simulator。因此只有外层service参数不足，以下为明确且非金融的适配设计。
4: 
5: ## 注入链与绑定
6: 
7: 采用显式可选keyword参数，不使用全局变量、thread-local/contextvars、monkeypatch或事后从UUID猜所有权：TaskService/可信worker → services.backtest的simulate/_execute/resume/replay → Simulator实例的execution_context → 每次_risk_portfolio的P4 child context → portfolio.service/ExperimentLedger.start。_risk_portfolio和_submit的verify_portfolio_result同时取得对应expected child binding。上下文只提供登记/解析/验证/安全取消能力，不选择因子、不改风险或记账。
8: 
9: TaskAuthority由可信本地launcher连接既定workspace任务库并在worker进程内创建；前端/JSON/普通用户draft不能提供authority、context、run_id、root或trusted=true。核心入口拿到上下文后必须用已配置authority核实际持久化记录和当前claim，不能接受调用者自报布尔或任意duck-typed函数返回“可信”。此为本地工程应用完整性协议，不是OS隔离/密码签名；任意拥有进程/磁盘写权的主体隔离仍属延期事项，不声称Python对象不可伪造。
10: 
11: 每个绑定的不可变元组为(workspace_id, task_id, task_kind, plan_hash, slot_id, service_kind, decision_index, decision_time_UTC, source_request_hash, adapted_request_hash, parent_slot_id, parent_execution_run_id, child_run_id, physical_ledger_root, core_config_hash, code_sha, code_bundle, core_lock_hash, ui_lock_hash)。不适用字段显式null。P4的parent是实际当前B执行UUID；重放时是新的replay执行UUID，原source P5 UUID另列source_ref，绝不冒用原任务的孩子。
12: 
13: 初始Task事务先登记R/B（或replay执行）固定slot和UUID。ResolvedPlan封闭时，从P5请求的完整有序decision集合预分配P[i] slot、UUID、预期parent及root。P4实际适配请求依赖当时真实账户，不能提前伪造hash：_risk_portfolio获得原adapt_portfolio返回的request后、调用construct之前，authority在SQLite事务中以同一task/parent/index/time/source hash核对预分配记录，保存适配raw bytes/hash和core_config_hash，状态由ALLOCATED一次性变BOUND/START_INTENT，提交后才能创建P4目录/初始事件。已绑定的不同hash、时间、root或父run拒绝；不能在P4返回后补填原来不存在的登记。
14: 
15: 新的可选TaskRunContext将不可变binding_hash写入核心初始lineage并由start核配置/UUID/root/服务匹配。当前worker claim/epoch每次由authority验证：不可变孩子归属不随接管重写；恢复新claim追加授权接管事件，旧handle epoch失效。禁止两个并发claim执行同一slot；不同task/P5实例有各自不可变context引用，SQLite事务约束和原文件锁互补，不以全局“当前任务”切换。
16: 
17: ## 固定目录，不移动原P5内部P4
18: 
19: ```text
20: workspace/
21:   task-control/tasks.sqlite
22:   tasks/<task_id>/request,plan,completion,task-events...
23:   research-runs/<P3_uuid>/                 # 所有研究Task共享家族/试验预算根
24:   backtest-runs/<B_uuid>/                 # P5原物理根
25:     portfolio-runs/<P4_uuid>/             # 继续使用P5现有内部根

29: 
30: “共享根”要求准确收窄到P3研究家族/预算，不强迫P5内部P4移到全局目录。任务库维护全局索引，但必须记录并验证上图真实物理根。P5的P4 root恒等于guard_path(parent_execution_root / portfolio-runs)，不能由网页传路径或从合法UUID拼另一个任务根；原终态manifest、candidate/risk/result原字节与发布审计、P1/P3原输入来源的所有检查全部保留。目录枚举/权限错误、链接或reparse逃逸不能当空目录成功。
31: 
32: ## 内部断点与恢复/重放
33: 
34: 内部P4合法终态已写但slot映射未写：只可找到原先已BOUND/START_INTENT的slot，核全部元组、初始binding/config/lineage、物理根及原始终态门禁后追加该slot VERIFIED，不新建P4、不提升Task。若无预登记或binding缺失，即使UUID和manifest合法也RECOVERY_REQUIRED。相同UUID换根、换parent/decision/请求、其他task的合法P4、重复别名、未知子目录都拒绝。
35: 
36: P5按原resume条件重放已提交事务prefix时，execution_context先解析同一index的原P4 slot。已有已核终态且适配raw request相同则返回原P4结果，经原provider校验后继续原事务比较；不能再调construct创建第二个P4。若尚未启动且可证明ALLOCATED则首次调用；半初始化/非终态P4无现成恢复协议，一律RECOVERY_REQUIRED，不借P5 resume重做P4。适配request与旧绑定不同则拒绝，不改输入迎合重放。已提交Fill及原错误记录不覆盖。
37: 
38: replay_engineering使用新的Task replay context/预分配目标根和内部P4 slots，原P5 source只读；原金融request_id仍保持以维持原确定性订单/事件算法，任务执行UUID另行绑定。完成后Task层封存本次返回、比较证据、目标事务和内部P4清单；仅NUMERICAL_REPLAY_VERIFIED字符串而缺本次目标/所有权/比较证据不足以使Task成功。旧无context的所有公开API继续原随机UUID、原目录/验证流程与行为，不连接任务数据库、不改旧结果/Ref或强迫旧run迁移。

1: # 精确十进制参考、显示舍入与明确量程（G1候选）
2: 
3: WORK-P6-G1-003在原参考中已实际复现：39位小百分比除100静默舍入，30位以上大金额quantize抛InvalidOperation。原32组正确答案的整个GOLDEN_CANDIDATES.json保持原始字节；新边界另存SUPPLEMENTAL_CANDIDATES.json。当前只修设计参考，不代表UI已实现或该发现独立关闭。
4: 
5: 拟新增P6输入/参考只接受ASCII普通有限十进制字符串：可选正负号、至少一个数字、可选小数点与数字；允许`.5`，不接受空白、Unicode数字、指数、NaN/Infinity或非字符串。输入数字位总数（含前导/小数零）最多4096，原文本长度最多4098；先检查长度/语法/位数，超限明确REFERENCE_NUMERIC_RANGE，语法错误REFERENCE_NUMERIC_SYNTAX，均保留原字符串/其hash，不截断、不静默舍入。本量程是待G1及后续用户实施授权确认的新增薄适配方案，**不修改P1–P5既有数值API或core锁**。
6: 
7: 数值解析只得到有符号整数coefficient及十进制scale。百分比除100仅将scale增加2，转成普通十进制并移除无意义尾零，不调用Decimal除法或normalize。金额/IC/百分比视图用整数商余数：对目标最小显示单位计算绝对商q、余r，`2r>den`或`2r==den且q为奇数`时进位，再恢复符号；此即HALF_EVEN。分组分隔符通过十进制字符串处理。输出的进位可比输入多一位，百分比视图可增加有限位数，最长仍低于Python默认整数文本限制；不调整全局Decimal context或int_max_str_digits。
8: 
9: 除声明的视图位数外不进行任何舍入：money保留2位、ic_display保留4位、percent_display先精确乘100再保留4位；展示零统一为无负号的`0.00`/`0.0000%`。权重/请求数值没有视图舍入，`-12.50%`精确为`-0.125`。原始数据/配置、精确资金/数量及原报告不回写，原字符串始终可读取/下载；JS图表无法准确表达的值仍按既定精度警告与原始表格策略处理。
10: 
11: 独立字面边界至少包括两条原反例、正负长百分比/超小数、整数与跨位进位大金额、正负HALF_EVEN（奇/偶分位及零）、4096位边界/4097位拒绝、非有限/指数/Unicode/类型拒绝。设计参考还应在不同ambient Decimal精度和陷阱下得到相同结果，且使用Fraction/字面数等另一个参考独立核数值；不得用被测转换函数生成expected。有效范围内的量值不能因默认28位精度失败。
12: 
13: 通过此数值词法/量程检查不等于通过金融领域校验：P3/P4/P5仍按原schema、有限样本、权重/风险/可执行量等明确接受或拒绝；不得为适配4096位展示而放宽或重写旧金融计算。

16: def decimal_parts(text):

20:         raise ReferenceNumberError("REFERENCE_NUMERIC_RANGE")
21:     sign = -1 if text.startswith("-") else 1
22:     body = text[1:] if text.startswith(("-", "+")) else text
23:     parts = body.split(".")
24:     if len(parts) > 2:
25:         raise ReferenceNumberError("REFERENCE_NUMERIC_SYNTAX")
26:     whole = parts[0]
27:     fraction = parts[1] if len(parts) == 2 else ""
28:     digits = whole + fraction
29:     if not digits or (len(parts) == 2 and not fraction) or any(c not in "0123456789" for c in digits):
30:         raise ReferenceNumberError("REFERENCE_NUMERIC_SYNTAX")
31:     if len(digits) > MAX_DIGITS:
32:         raise ReferenceNumberError("REFERENCE_NUMERIC_RANGE")
33:     return sign * int(digits), len(fraction)

36: def exact_text(coefficient, scale, *, trim=True):
37:     negative = coefficient < 0
38:     digits = str(abs(coefficient))
39:     if scale:
40:         digits = digits.zfill(scale + 1)
41:         whole, fraction = digits[:-scale], digits[-scale:]
42:         if trim:
43:             fraction = fraction.rstrip("0")
44:         result = whole + ("." + fraction if fraction else "")
45:     else:
46:         result = digits
47:     return ("-" if negative else "") + result

50: def rounded_units(coefficient, scale, places):
51:     if scale <= places:
52:         return coefficient * 10 ** (places - scale)
53:     denominator = 10 ** (scale - places)
54:     q, r = divmod(abs(coefficient), denominator)
55:     if 2 * r > denominator or (2 * r == denominator and q % 2):
56:         q += 1
57:     return -q if coefficient < 0 else q
