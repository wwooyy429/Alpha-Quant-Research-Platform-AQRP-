# 精确十进制参考、显示舍入与明确量程（G1候选）

WORK-P6-G1-003在原参考中已实际复现：39位小百分比除100静默舍入，30位以上大金额quantize抛InvalidOperation。原32组正确答案的整个GOLDEN_CANDIDATES.json保持原始字节；新边界另存SUPPLEMENTAL_CANDIDATES.json。当前只修设计参考，不代表UI已实现或该发现独立关闭。

拟新增P6输入/参考只接受ASCII普通有限十进制字符串：可选正负号、至少一个数字、可选小数点与数字；允许`.5`，不接受空白、Unicode数字、指数、NaN/Infinity或非字符串。输入数字位总数（含前导/小数零）最多4096，原文本长度最多4098；先检查长度/语法/位数，超限明确REFERENCE_NUMERIC_RANGE，语法错误REFERENCE_NUMERIC_SYNTAX，均保留原字符串/其hash，不截断、不静默舍入。本量程是待G1及后续用户实施授权确认的新增薄适配方案，**不修改P1–P5既有数值API或core锁**。

数值解析只得到有符号整数coefficient及十进制scale。百分比除100仅将scale增加2，转成普通十进制并移除无意义尾零，不调用Decimal除法或normalize。金额/IC/百分比视图用整数商余数：对目标最小显示单位计算绝对商q、余r，`2r>den`或`2r==den且q为奇数`时进位，再恢复符号；此即HALF_EVEN。分组分隔符通过十进制字符串处理。输出的进位可比输入多一位，百分比视图可增加有限位数，最长仍低于Python默认整数文本限制；不调整全局Decimal context或int_max_str_digits。

除声明的视图位数外不进行任何舍入：money保留2位、ic_display保留4位、percent_display先精确乘100再保留4位；展示零统一为无负号的`0.00`/`0.0000%`。权重/请求数值没有视图舍入，`-12.50%`精确为`-0.125`。原始数据/配置、精确资金/数量及原报告不回写，原字符串始终可读取/下载；JS图表无法准确表达的值仍按既定精度警告与原始表格策略处理。

独立字面边界至少包括两条原反例、正负长百分比/超小数、整数与跨位进位大金额、正负HALF_EVEN（奇/偶分位及零）、4096位边界/4097位拒绝、非有限/指数/Unicode/类型拒绝。设计参考还应在不同ambient Decimal精度和陷阱下得到相同结果，且使用Fraction/字面数等另一个参考独立核数值；不得用被测转换函数生成expected。有效范围内的量值不能因默认28位精度失败。

通过此数值词法/量程检查不等于通过金融领域校验：P3/P4/P5仍按原schema、有限样本、权重/风险/可执行量等明确接受或拒绝；不得为适配4096位展示而放宽或重写旧金融计算。
