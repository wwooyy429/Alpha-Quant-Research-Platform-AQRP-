# AQRP V3.1 — 架构与质量控制补充条款

本文件对 AQRP V3.0 进行针对性修订。除明确修订的部分外，继续保留 V3.0 已确定的技术架构、功能需求、阶段开发制度和人工验收机制。

## 1. 阶段依赖约束

所有验收条件必须与实际开发阶段的模块可用性一致。

Phase 2 只验证 Factor Registry 的接口、注册、替换和版本兼容性。

Phase 3 验证因子替换后完整因子研究流程仍可运行。

Phase 5 验证因子替换后组合与回测流程仍可运行。

Phase 6 验证网页与 CLI 的因子选择和研究结果一致。

Phase 7 执行完整的因子替换端到端测试。

禁止为了满足尚未具备依赖条件的验收要求，未经批准提前开发后续阶段模块。

## 2. 数据契约

Phase 0 必须制定统一的数据契约，覆盖：

- 唯一证券标识及所属市场。
- 货币与数据单位。
- 时间戳、时区与交易日历。
- event_time、available_at、decision_time。
- 复权、分红、拆股及公司行动处理。
- 停牌、退市及历史股票池。
- 数据缺失、重复和异常语义。
- 数据快照版本及校验信息。

所有模块必须遵守统一契约。

## 3. 回测事件与账本契约

Phase 0 必须定义完整的回测事件状态机及时间顺序。

明确行情确认、信号生成、组合决策、订单提交、撮合、成交、资金更新和估值的先后关系。

Phase 5 必须对这些规则建立自动化测试及已知答案案例。

禁止在信号可获得时间之前生成可执行订单。

## 4. 因子研究及样本外隔离

因子方向、参数、预处理方案及预测期限，应在预先指定的开发数据中确定。

最终独立测试集不得反复用于因子选择或参数调整。

所有候选因子、参数实验和筛选过程必须保留记录。

系统必须识别多重假设检验、重复试验及过拟合风险。

正式批准因子时，必须记录预先设定的通过标准和实际验证证据。

## 5. MVP 与完整系统分离

将功能明确划分为：

- MVP
- Competition Ready
- Advanced Research
- Production Extensions

每项需求必须说明属于哪一级别、开发阶段和依赖条件。

不得为了实现完整系统愿景，而在早期阶段未经批准增加复杂功能。

任何未实现能力必须明确标记为 Planned、Unsupported 或 Deferred，不能以模拟结果冒充完整实现。

## 6. 独立测试答案

Golden Test Dataset 必须保留独立核对过的预期结果、计算依据和数值容差。

不能使用待验证函数自身生成测试期望值。

关键金融数学及资金计算必须同时接受边界测试、性质测试及独立参考核对。

## 7. 安全和版本管理

固定开发环境及依赖版本。

新因子代码必须经过审查后才能进入已批准的执行环境。

实验采用唯一 run_id、不可变配置快照及可验证的数据和代码版本标识。

严禁未经授权运行真实订单，或提交真实 API 密钥到代码仓库。

## 8. Phase 0 增加专项审计

在 V3.0 原有 Phase 0 交付之外，还必须提交：

1. 阶段依赖一致性检查。
2. 数据契约完整性审计。
3. 回测事件时序设计审计。
4. 样本外隔离及多重检验方案。
5. MVP 与完整需求分级表。
6. 自动化测试与人工审查证据要求。

上述成果必须与需求追踪矩阵保持一致。

如存在冲突或无法决定的设计事项，应明确列出，等待用户批准。

Phase 0 完成后停止，不得自动进入 Phase 1。
